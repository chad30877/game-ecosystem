## Status

resolved

## What to build

建立可辨識實際執行產物的建置與執行來源資料，統一專案內受管模擬產物位置，讓後續記錄、回放與清理能確認歸屬及是否仍被使用。

需求依據：[正式規格](../spec.md) S02、S06、S08；同時遵守 S01 的範圍與授權、S07 的證據保留及 S09 的交付要求。

## Blocked by

無。

## 驗收條件

- [x] 新成功建置、當前採用建置、執行與播放器可核對同一份建置；不同建置不因規則名稱或 Git commit 相同而被當成相同來源，未知舊來源不猜補。
- [x] 每次啟動有獨立執行識別，可包含多個世界輪次；來源涵蓋配置、種子、控制方式、適用場景／版本與記錄意圖。
- [x] 新資料使用專案內專用受管目錄；自訂輸出與非模擬檔案不因入口收到路徑就自動被登記為可刪範圍。
- [x] 建置失敗不切換採用狀態或觸發淘汰；成功採用可供後續清理明確辨識，仍在使用舊建置的執行／播放保留可查核的使用狀態。
- [x] 活躍執行／播放狀態可跨程序核對，不能只依殘留 running 標記推斷；正常與異常退出均可由後續流程判斷是否仍在使用。
- [x] 以兩份建置、多輪執行、自訂輸出與失敗建置的隔離情境驗證來源契約；記錄路徑與識別的實作選擇及人工核對方式。

## 人工測試方式

在兩份成功建置各啟動一次，再模擬失敗建置，查看執行歸屬與採用建置；播放中的檔案應仍標示使用中。這是後續驗收方向，本次未執行；實作後補入確切命令及結果。
