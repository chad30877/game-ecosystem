# 01：可觀察的食物枯竭與恢復

> 2026-10-23 保存狀態更新：本文 artifacts 路徑保留為歷史驗證來源；大型原始紀錄與舊模型已淘汰，摘要及指定短回放的保存範圍見[產物清理紀錄](../../../docs/artifact-retention.md)。歷史操作範例須改用仍存在或新產生的來源。

**What to build:** 使用者可在既有世界入口觀看不同生長類型的食物被吃光、休養、恢復至門檻，再重新採食；規則展示與學習橋接收到相同的可採食狀態。

**Blocked by:** 無（可立即開始）。

**Status:** resolved

- [x] 配置可指定生長類型、容量、生長速度、休養時間與恢復門檻；驗證非法值，完整參數寫入執行紀錄。
- [x] 可採食、休養及恢復生長各階段符合規格；門檻前無法採食，存量維持合法範圍。
- [x] 培育不解除休養，恢復生長時可促進生長；播種原有成熟等待與技能成本仍有效。
- [x] 可見及無畫面固定場景可重現一個完整枯竭／恢復循環；畫面以簡潔狀態呈現差異，策略可辨識可採食狀態。
- [x] 必要的世界與觀察版本隨介面變更更新，拒絕不相容舊模型；既有新版本 bridge 可往返。
- [x] 記錄人工操作與對外事件證據，通過建置及相關技能、覓食回歸；不新增測試檔。

## 完成紀錄

- 世界執行入口記錄 `food_depleted`、`food_recovering`、`food_available`；食物觀察欄位只在可採食階段為 1。培育於休養期無效，播種仍等待原有成熟時間。
- 固定種子 5、200 步指定動作：第 6 步枯竭、第 16 步開始恢復、第 28 步重新可採食；可見與無畫面執行的逐步食物狀態及事件一致。紀錄位於 `artifacts/runs/forage-20261022-220528-5dbf80a8/` 與 `artifacts/runs/forage-20261022-220702-257328b4/`。
- Unity 建置、八個既有指定動作情境、一般 bridge 與覓食 Python 觀察往返通過；記錄版本與模型相容簽章更新為 `resources-v2`。未新增測試檔。
