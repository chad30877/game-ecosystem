## S01 目標、範圍與執行界線

- 快速開發期間以當前建置的觀察與診斷為主，降低逐步記錄、歷史相容與舊產物維護成本；不修改世界規則、果實數值或生物 AI 行為。
- 使用者從模擬畫面看現象；輸出資料供 Codex 或其他 LLM 讀取，不提供生物控制器使用，不自動呼叫 LLM，也不新增統計儀表板、永久釘選介面或清理常駐服務。
- 本輪涵蓋建置與執行識別、記錄／錄製／回放、保留與清理、相關入口、必要驗收與文件；六場生態觀察、果實產量調整、幼體照顧長期對照、PPO 與混合控制實驗不啟動。
- 正式規格是需求依據，訪談為背景；實作須另取得使用者授權，前置全部 resolved 後才可 claimed。不得在本次文件發佈時建置、修改程式、執行清理或宣稱功能驗收通過。

## S02 建置、執行與管理歸屬

- 一次啟動到停止為一次執行，可包含多個世界輪次；自動或手動重建開始新輪次，不能把各輪次當成不同執行來計算保留數量。
- 以可辨識實際執行產物的建置識別區分資料。單靠規則名稱、動作／格式版本或 Git commit 不足以識別建置；識別的生成與保存方式由實作選擇，須能可靠核對來源與播放器。
- 每次執行保存執行識別、建置識別、配置、種子、控制方式、適用的場景與版本、記錄模式、起訖及停止／資料完整性狀態。來源未知須如實表示，不猜測歷史建置。
- 新建置成功且成為日常使用版本後才切換管理中的當前建置並觸發淘汰；建置失敗不切換、不清舊資料。仍使用舊建置的執行／播放須受保護，結束後再處理。
- 新受管資料集中於專案內一個專用模擬產物根目錄，與現有混雜 artifacts 分開；實作選定後在入口與文件統一。必須可辨識受管執行、其檔案歸屬及仍在執行／播放的使用者，不能只依目錄名稱、日期或殘留 running 字樣判定。
- 自訂輸出至受管根目錄以外、或另存的複本不自動追蹤刪除；記錄與回放完整性政策仍適用。資料複製不帶來跨建置可播放的承諾。

## S03 日常輕量統計與來源資訊

- 所有一般模擬入口預設僅產生精簡結果摘要、群體時間序列與來源資訊。不能透過 reset、加入／死亡事件、退出紀錄或其他非 step 記錄，變相持續保存完整個體狀態。
- 以模擬時間每一秒保存一筆群體樣本，並保存輪次起訖及正常提前停止的最後狀態摘要；暫停不以牆鐘時間產生樣本，重建後以輪次區分時間與累計數。事件累計依實際發生持續更新，不只在抽樣時才計數。
- 群體統計至少涵蓋各物種人口、出生／死亡、低飽食情況及飽食統計，來源數、來源／攜帶／地面果實存量，以及產果、吃掉、腐爛、交付、掉落、來源到期損失的累計流量。沿用既有領域語意與門檻，不能為記錄改變生態機制。
- 精簡摘要提供人口、營養與供給的起訖、變化範圍、累計事件、觀察時間及停止原因，附來源與時間序列入口；讓 LLM 先讀摘要再按需要讀特定時段。多輪資料不得相互覆蓋或將不同世界連成同一條生態歷史。
- 來源資訊保存 S02 的配置等重現線索；不把相同種子或來源資料宣稱為跨建置結果一致的保證。摘要不得從不完整資料推造未知結果。
- 未明確開啟完整錄製時，不寫逐步位置、情報、決策與完整世界快照，不產生可逐步回放的來源。既有詳細診斷只能明確要求才輸出，不能由入口默認加開或抵銷輕量預設。

## S04 完整錄製、封裝與回放

- 啟動前明確開啟完整錄製，記下該次執行所有輪次；不增加執行中切換。各輪次分段，包含初始快照與後續連續狀態；正常退出、執行步數上限與世界自然結束須可區分。
- 正常提前停止仍可封裝已錄片段，不要求必須等到全滅或世界時間上限；手動重建與自然重建均保存正確分段及結束語意。無有效狀態、缺漏或毀損資料不得冒充成功錄製。
- 同建置回放依保存快照還原，前後跳轉不重跑世界、不重新感知；保存世界真值、當時個體情報與狀態的原有區別。不同或無法確認建置的資料明確拒絕，不套用現行規則猜讀。
- 退役 v9–v14 專用讀取／轉換分支與必須提供歷史代表檔的驗收。不遷移舊檔，也不因舊規則名稱仍相同而推定相容。規則、動作與資料格式識別仍各自表達其用途。
- 成功完整錄製是整次執行的所有必要分段及來源資訊均通過檢查；應核對輪次、影格連續性、完整性及封裝內容，不能只以檔案存在或其中一輪成功判定。
- 需保留但未包含於回放的來源資訊、統計與停止原因先妥善保存。所有相關分段檢查完成後才移除冗餘完整來源；任一分段失敗或仍有未保存資訊時保留原始來源，不取代上一份成功錄製。

## S05 記錄失敗與資料狀態

- 初始化無法建立或寫入必要紀錄時，明確回報啟動失敗。
- 執行途中記錄寫入失敗時，停止本次資料記錄、標示不完整，世界更新、出生死亡同步及畫面觀察繼續；不能讓記錄例外中斷世界步驟的後半段。
- 可見觀察提供簡短失敗狀態；無畫面入口與自動驗收必須能判斷資料失敗，不得只因模擬仍能執行就回報資料產出成功。錯誤回報不可只依賴同一個已失效的資料寫入位置。
- 崩潰、強制終止、結尾寫入／關閉失敗，或封裝失敗均不能產生假的完整標記。不新增殘缺回放修復或播放；保留實際已寫入的診斷與來源，之後依 S06 淘汰。
- 世界輪次終止、使用者提前停止、執行步數上限與資料失敗分別記錄；無法確定原因時標為未知或不完整，不將崩潰猜成正常停止。

## S06 保留與自動清理

- 當前建置保留最近五次已停止執行的輕量資料，包含失敗場次；依實際停止先後判定，不把仍執行中的資料算成可淘汰候選。
- 另保留最近一次成功完整錄製的全部分段與必要摘要／來源資訊，即使它不在最近五次內。其他錄製不因仍在五次範圍內而永久保留其完整大檔；其輕量資料依五次規則處理。
- 新錄製全批成功後才替換上一份成功錄製；失敗錄製不替換，失敗來源隨所屬執行淘汰。仍在播放或寫入的資料延後處理，不能由另一個執行或建置過早刪除。
- 新建置採用後，舊建置模擬統計、來源、回放、日誌、失敗殘檔及原始驗收素材可淘汰；五次／一次規則不保留跨建置歷史。已寫入 Git 的正式文件與結果不屬於淘汰範圍。
- 清理掛在建置／執行流程，不另啟常駐服務。只刪受管根目錄內有可靠歸屬、符合政策且非活躍使用的產物；正規化實際路徑並排除越界／連結導向外部或歸屬不明的目標。錯誤不能默默算清理成功，重試不得誤刪保留資料。
- 模型、開發環境、工具快取、非模擬檔案、自訂輸出與另存複本不納入自動淘汰；不能把整個 artifacts 或任意 OutputRoot 視為可遞迴清空的範圍。

## S07 LLM 工作流程與首次舊資料整理

- 日常固定淘汰由程式執行，LLM 負責首次辨識混雜舊資料、測試依賴與文件引用，以及後續規則調整。
- 開發需跨建置或超過五次執行比較時，LLM 須在觸發淘汰前另存本任務仍需的資料至專案內受管目錄之外。分析完成後整理有效結果至正式文件並清除臨時大檔，不新增永久釘選；另存舊回放仍無跨建置播放保證。
- 首次整理需產出當時的分類清單，辨識既有模擬產物、現行測試固定素材及不屬於本輪範圍的檔案。舊資料缺乏可靠建置識別時不猜測，依已確認舊模擬資料範圍處理，不自動掃除專案外資料。
- 先安置仍有效的測試素材、退役歷史回放驗收依賴並整理必要正式結果，再淘汰已識別的舊模擬資料。保留精簡整理結果、範圍與限制；不得改寫歷史驗收結論或虛稱本次修復了原相容問題。
- 本次只發佈規格。首次整理及任何實際刪除屬後續取得實作授權後的任務，不能以文件發佈作為立即清理的授權。

## S08 入口與既有任務關係

- 一般可見／無畫面模擬、腳本入口及直接啟動 Player 均須遵守輕量預設；相關 bridge、固定模型觀察及驗收工具不得暗中重新打開全量紀錄。只調整記錄契約所需整合，不進行 PPO 訓練、模型遷移或成效實驗。
- ReloadRun 等重跑入口須讀取新的來源資訊，與讀快照回放區分；只保證現有必要功能在本輪契約下正常，不新增歷史重跑相容承諾。既有詳細診斷、指定場景與素材生成工具須採明確記錄意圖。
- [fruit-supply-and-flow 11](../../fruit-supply-and-flow/issues/11-record-replay.md) 保留 resolved 與原證據；新的未來回放政策由本規格承接，現有程式直到實作落地前仍可能包含歷史分支。

## S09 驗收與交付

- 每張任務附可重現的檢查與結果；整合驗收涵蓋輕量資料與已知情境統計一致、多輪／正常提前停止錄製、前後跳轉、錯建置與損壞拒絕、初始化及執行中 I/O 失敗、跨輪全批成功判定。
- 保留驗收覆蓋五次／一次、成功／失敗混合、錄製超出五次時必要資訊、並行執行與播放保護、建置失敗不清理、新建置採用淘汰、越界及未知資料不誤刪。清理測試先用隔離的專案內測試產物，不以未分類真實歷史檔試刪。
- 驗證建置、必要 bridge／入口與可見操作；檢查記錄模式不改變同建置同配置同種子的世界結果。只執行足以驗證此契約的短程情境，不用六場長期生態或 PPO 代替本輪驗收。
- 修改 PowerShell 腳本須保留 UTF-8 BOM，並以 PowerShell 5.1 執行 scripts/check-world-script.ps1；環境、依賴與快取維持專案內既有慣例。每次改動完成後提交繁體中文 Git commit，記錄人工測試方式。
- 通過功能與整合驗收後更新實際操作文件、資料契約、LLM 工作指引、清理結果與 future ideas。只在本功能全部任務完成後，將本資料夾整份移至 .scratch/archive/ 並更新引用；不移動尚未結案的 fruit-supply-and-flow。
