## 第二輪：待回答

### Q4 輕量統計的用途與內容

建議保留能看出人口與供給變化的低頻時序統計及結束摘要：各物種人口、出生／死亡、低飽食情況、來源數、果實存量與產出／吃掉／腐爛等累計流量；另留配置、種子、控制方式、程式來源識別與實際停止原因。日常不留逐個體每步位置、情報與決策明細。採樣間隔與精確欄位待本題確認後細化。

### Q5 「同一套程式」的支援邊界

建議快速開發期先以產生回放的同一份建置為保證範圍；換建置可明確拒絕舊回放，即使規則版本名稱相同。代價是只有畫面或其他相容改動的重新建置，也不保證能讀先前檔案。這是待確認政策，識別方式與是否保存舊執行檔仍待後續決定。

### Q6 錄製操作與正常提前停止

建議先採啟動時明確開啟錄製，不新增執行中切換；正常提前停止時，已錄到的連續片段仍能封裝播放，標示觀察提前結束，不冒充生態輪次自然結束。崩潰、強制終止或寫入失敗的處理另待此原則確認後討論。

### Q7 封裝後的來源保留

建議允許自動移除本次執行中已確認冗餘的完整來源，但須先完成回放檢查，並將需保留、未包含於回放的統計與來源資訊妥善保存；失敗、尚未封裝的輪次或仍有未保存資訊時保留來源。這項新政策尚未確認，不授權本次刪除檔案。

### Q8 成品與既有資料的清理

建議輕量統計、來源資訊及回放成品不按天數或容量自動淘汰；沿用先盤點、列出清單，再明確執行清理。既有產物也只走盤點流程，不因新記錄預設或停止歷史相容承諾就直接刪除。與 Q7 的本次執行重複來源處理分開。

## 現行記錄流程查核

以下是 2026-10-30 的程式現況，不是本輪的新規格。

- 一般 `world.ps1 -Mode forage` 未加旗標時，`SummaryLog` 與 `MetricsLog` 關閉，`world.jsonl` 每步保存完整世界狀態；未指定 `RecordEpisodes` 時不自動封裝成回放。
- 加上 `SummaryLog` 後，逐步完整狀態改為事件發生、每 50 步或終止時的精簡樣本，包含人口、統計、果實流量／存量等；非 step 記錄仍可能含完整狀態。這不是只留最後一份結果報告。
- 指定 `RecordEpisodes` 時，forage 入口自動開啟精簡主紀錄，指定輪次的完整狀態另存 `record-source.jsonl`；正常執行結束後封裝成各輪回放及容量／雜湊側錄。封裝要求輪次完整結束、影格連續且至少兩幀，失敗保留來源；成功也不刪來源。
- `MetricsLog` 是額外的逐步個體診斷，並非小型彙整報告，開啟後仍可能累積大量資料。
- `training/summarize.py` 是另一套事後彙整；它忽略沒有 `state` 的樣本，部分事件統計依賴完整 step。不能假設現有精簡紀錄直接交給它就有相同統計；forage 也未自動呼叫它。
- 入口存在差異：固定模型觀察的部分啟動路徑錄製時未自動開啟摘要，可能同時留下完整主紀錄與錄製來源；新政策需涵蓋各入口。
- 一般 run 目前沒有 Git commit、工作目錄異動狀態或實際建置指紋；規則名稱與動作版本不能識別同名版本下的程式差異。訓練／模型觀察另有 DLL 雜湊，但不是一般 forage 的既有能力。
- 錄製只在啟動時指定輪次，沒有執行中切換。正常關閉或達整體步數上限只寫 `observation_end`，封裝器僅承認 `episode_end`，因此未完輪次仍不能封裝；現有結尾也未完整區分使用者停止與執行步數上限。
- 封裝回放只保留 `reset`／`step` 的狀態及部分 run 欄位；來源另外包含個體加入／死亡、輪次結束、觀察停止等紀錄，也可能包含多個輪次。播放不需要來源，不等於全部來源資訊都已另存；只封裝其中一輪不足以認定整份來源冗餘。
